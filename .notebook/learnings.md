- 2026-10-15 [src/server/lib/audit/lighthouse.ts, src/server/workflows/siteAuditWorkflowPhases.ts]: fetchLighthouseResult catches every error, including AppError refusals, and records it as a Lighthouse result row's errorMessage. A budget refusal there would look like a provider failure, and the audit still completes. (T-0002)
- 2026-10-15 [src/server/workflows/RankCheckWorkflow.ts, src/server/workflows/rankCheckPaths.ts]: Rank workflow batch errors are swallowed into batchError and never reach markRankCheckRunFailed, so lastSkipReason is only set from the hosted prepare-step check. Failed live batches and failed queued posts also trigger paid fallbacks (queue and live respectively). (T-0002)
- 2026-10-15 [src/server/workflows/**, src/db/pg/client.ts, src/server/lib/dataforseo/client.ts]: In Postgres mode pgDb (and so runBatch) throws a plain Error outside a withPgClient/pgStep scope. ALS does not cross step.do, so any DB write reached from a Workflow step, including one inside the DataForSEO client, must run inside pgStep.
- 2026-10-15 [src/server/features/dashboard/**]: Dashboard caches (DashboardCacheService) are keyed by organizationId and params, not projectId: one project's paid refresh feeds another project's cached read in the same org.
- 2026-10-16 [src/db/runBatch.ts, src/server/features/**/repositories/*.ts]: drizzle 0.45 `tx.insert(t).select((qb) => qb.select({...}))` does not type-check with the d1Db-typed runBatch tx; use `insert(t).select(sql`SELECT ...`)` with every column in table-definition order (ProjectWebsiteRepository precedent). Postgres coerces untyped params in INSERT...SELECT to the target column types. (T-0001)
- 2026-10-16 [vite.config.ts, src/**/*.ts]: Vitest config swallows console.log from passing tests (even with --silent=false), and the repo's TS lib lacks Array#toSorted while oxlint forbids Array#sort; use remeda sort/sortBy/firstBy. (T-0001)
- 2026-10-16 [drizzle/pg/*.sql, src/db/pg/better-auth-schema.ts]: pg migrations make organization.created_at timestamptz while the SQLite one is integer; raw seed SQL for Postgres needs now(), not text. (T-0001)
- 2026-10-16 [src/routeTree.gen.ts, vite.config.ts]: `pnpm exec vite build` works offline in a worktree and is the way to regenerate src/routeTree.gen.ts after adding route files; it writes only to the gitignored dist/ besides the route tree. (T-0005)
- 2026-10-16 [src/server/workflows/**]: Cloudflare Workflows persists a step's terminal error (storage key '<cacheKey>-error' in miniflare's workflows binding.worker.js) and rethrows it on replay without re-running the step. The stored error is structured-cloned, so AppError's class is lost and only name/message survive: recognise step errors by message (asAppError works only when message is a bare ErrorCode).
- 2026-10-16 [src/server/workflows/**]: An error thrown across a Cloudflare Workflows step.do may lose its class; only the message reliably survives. Recognise an AppError after a step with asAppError(error), which needs message === bare ErrorCode. markRankCheckRunFailed's instanceof check for hosted INSUFFICIENT_CREDITS (message is not a code) may never match in production. (T-0006)
- 2026-10-16 [src/server/workflows/**, src/server/features/ai-visibility/services/aiVisibilityCollection.ts]: A paid Workflow step's persisted output shape cannot change safely: a run in flight across a deploy replays the old output, and renaming the step re-runs and re-bills it. Signal new outcomes from paid steps by throwing (or extend void-returning steps), and rebuild run-level state from step outcomes. (T-0006)
- 2026-10-16 [src/server/features/projects/services/ProjectDataforseoBudgetService.query.test.ts, src/serverFunctions/projectDataforseoBudgets.test.ts, src/db/runBatch.ts]: The SQL-backed tests use in-memory libsql on one client, so batches run one at a time. A 'concurrent' test there cannot exercise Postgres row locks and passes even with the lock removed. The repo has no Postgres test infrastructure (no PGlite or containers), so Postgres-only SQL behaviour needs a manual check. (T-0007)
- 2026-10-16 [src/server/workflows/siteAuditWorkflowPhases.ts, .oxlintrc.json]: siteAuditWorkflowPhases.ts sits exactly at oxlint's eslint/max-lines cap of 400. Blank and comment lines don't count, so `wc -l` (467) doesn't show it. Adding any code line fails `pnpm lint`; fold changes into existing lines or split the file. (T-0008)
- 2026-10-16 [src/server/lib/dataforseo/**]: DataForSEO returns HTTP 200 with an in-body status_code for request-level refusals (40203 cost limit, 40210 funds, 40202/40209 rate limits) and still reports a top-level cost; only 401/402/404/500 change the HTTP status. Never infer 'unbilled' or 'ambiguous' from an AppError thrown after a parsed body: use the envelope cost.
- 2026-10-16 [.prettierignore]: `pnpm format:check` (prettier --check .) can exit 2 with an ENOENT on `.codegraph/codegraph.lock` while the codegraph indexer is writing. Prettier still reports all files formatted. Rerunning passes. Prettier does not ignore `.codegraph/`. (T-0009)
