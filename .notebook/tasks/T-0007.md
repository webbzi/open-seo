What it is: self-hosted deployments (AUTH_MODE not hosted) get a per-project DataForSEO ledger. Before every paid DataForSEO HTTP call the shared client admits an estimate against the project's optional monthly (UTC) and total USD limits and pause flag, in one atomic `runBatch` (ensure row, row lock, SQL-side check + insert); afterwards it settles each row with the provider-reported cost, releases provably unbilled calls, and leaves ambiguous ones pending (reported as estimated after 30 minutes). Hosted mode (Autumn credits) must be unchanged. The owner's plan: `/home/nicoeft/workspace/webbzi/open-seo/dataforseo-project-budgets.md`; the design as built: decision `dataforseo-project-ledger`; task reports in `/home/nicoeft/workspace/webbzi/open-seo/.notebook/reports/` (T-0001-a4, T-0004-a1/a2, T-0005-a1/a2, T-0006-*).

Read `docs/maintainers/review-guidelines.md` and `AGENTS.md` first: their hard invariants (tenant scoping, dual-dialect persistence, billing seams) and false-positive controls apply.

Hunt for, in order:
1. **Money correctness.** Any path where two admissions can spend the same room; where a paid HTTP call can leave this Worker without an admitted row (raw fetcher imports, retries, fallbacks, batch entries); where a cost is counted twice (queued task_post total vs task totals, duplicate settle); where a row is released although the provider may have billed; where a DB failure is shown as a budget refusal or a refusal as an infrastructure error.
2. **Hosted regression.** Any behavior change on the hosted branch of `meterDataforseoCalls`, `websiteResearch`, credit arithmetic, error mapping, or hosted refusal handling (`INSUFFICIENT_CREDITS`) that the plan did not ask for. `postRankCheckTasks` losing its 5xx retries is intended in both modes.
3. **Tenant scoping and authorization.** Every ledger read/write scoped by organization through `projects`; server functions take ids from context; limit changes and CSV export require `billing: ["manage"]`; hosted mode refuses the new server functions and hides the routes.
4. **Dual dialect.** SQL in `ProjectDataforseoRepository.ts` and the migrations on both D1/SQLite and Postgres (types, booleans, CASTs, INSERT ... SELECT column order, ISO timestamp comparisons); DB access from Workflow steps inside `pgStep`; settlement inside `waitUntil` on Postgres.
5. **Refusal semantics.** Schedules advance and record a distinct skip reason; refused runs issue no fallback paid attempts and keep partial results; free collection, cache reads and saved data still work at zero allowance; MCP and app copy never suggests buying credits.
6. **Tests.** Against AGENTS.md "Testing": tests that prove nothing, mock ORM chains, re-test a library, or a negative test rejected by a different guard than its name claims.
