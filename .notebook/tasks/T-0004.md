## Brief
# T2a: Gate every self-hosted paid DataForSEO call on the project ledger

## Goal

In self-hosted mode (`isHostedServerAuthMode()` false), every paid DataForSEO HTTP call made by this deployment is admitted against its project's budget before dispatch and settled with the provider-reported cost afterwards, through `ProjectDataforseoBudgetService` (landed in T-0001: `src/server/features/projects/services/ProjectDataforseoBudgetService.ts`). Hosted mode (Autumn credits) must behave exactly as today.

Service facts from T-0001 (report `/home/nicoeft/workspace/webbzi/open-seo/.notebook/reports/T-0001-a4.md`): `admit` requires a non-empty `operation`, throws `NOT_FOUND` for a project outside the org, returns ids in estimate order; `settle` Zod-parses each charged `costUsd` as finite and >= 0 and a bad one throws for the whole call, so map a missing/non-finite provider cost to `unknown` before calling it.

Design: decision `dataforseo-project-ledger` (read its Choice). Facts about every paid path, with file:line: report `/home/nicoeft/workspace/webbzi/open-seo/.notebook/reports/T-0002-a1.md`, sections 1, 2, 4, 5, 6. Read both before starting.

## Change

1. `src/server/lib/dataforseo/client.ts`
   - `meter()` and the two batch entries keep raw USD estimates; `meterDataforseoCalls` converts to credits with `creditsForProviderUsd` only on the hosted branch. No hosted markup or credit rounding on the self-hosted branch.
   - Each meter entry gets an explicit operation label (`"serp.live"`, `"keywords.related"`, ...), passed to `admit`.
   - The client takes a project-scoped customer: `BillingCustomerContext & { projectId: string }` (name it; export the type from client.ts). Propagate the required type through the service/workflow/MCP signatures that build a client (report T-0002 §1 lists them). The org-level `BillingCustomerContext` stays as is for org billing. If a site genuinely has no project, stop and ask; do not invent one. The self-hosted branch also asserts `projectId` at runtime (deserialized workflow payloads) with a plain Error: missing attribution is a bug, never permission to spend.
   - Self-hosted branch: `admit` once for the whole invocation (one estimate per call; a refusal throws before any fetch and rejects every call with that AppError), run the calls with `Promise.allSettled`, then one `settle` with one outcome per call:
     - success -> `charged` with `result.billing.costUsd`
     - `DataforseoChargedTaskError` -> `charged` with `error.billing.costUsd` (0 is a valid known charge)
     - provably unbilled: DataForSEO answered with an HTTP 4xx, or the fetcher threw before sending anything -> `released`. Read `core.ts` and `envelope.ts` to tell these apart; when you cannot prove it, it is not this case.
     - anything else (network, timeout, 5xx, parse failure without an envelope) -> `unknown` (row stays pending; reported as estimated later)
     - feature: `input.creditFeature ?? defaultFeature` at admission; for a null one, settle passes `mapDataforseoPathToCreditFeature(billing.path)` when a billing envelope exists.
   - Keep the `waitUntil(work)` registration around calls + settlement as the hosted branch does. A failed settlement write is logged with usage ids and project id and does not throw: the caller still gets its results. A failed admission (DB error) propagates as an infrastructure error and nothing is sent.
2. `src/server/lib/dataforseo/serp.ts`: `postRankCheckTasks` passes `maxServerErrorRetries: 0` like every other billed task_post (applies to both modes).
3. `src/server/features/projects/services/websiteResearch.ts`: in self-hosted mode each `search_competitors` query goes through the client's `serp.live` (each loop retry is its own admitted call). Hosted mode keeps today's raw `fetchLiveSerp` + `billResearchSpend` path unchanged. `billResearchSpend` already skips self-hosted, so nothing is recorded twice. A project refusal is not retried, and when it is the reason nothing succeeded, the research fails with that refusal code, not "Website research was incomplete" / INTERNAL_ERROR.
4. `src/server/lib/audit/lighthouse.ts`: a `PROJECT_BUDGET_EXCEEDED` / `PROJECT_DATAFORSEO_PAUSED` refusal yields the existing failed-result shape with a clear errorMessage ("Skipped: this project's DataForSEO allowance is used up" / "...paid usage is paused") and `console.info`, not `console.error`. Crawl results are untouched (already true).
5. MCP: `src/server/mcp/instrumentation.ts` `agentFacingError` rewrites the two codes for agents the way it rewrites `INSUFFICIENT_CREDITS`: project-specific, says retrying the same paid operation will not help until the monthly allowance resets, the limit is raised, or paid usage resumes in the project's API spending settings, and that saved/cached results remain available. Never suggest buying credits or changing budgets.

Hosted behavior stays byte-for-byte: same credits, same holds, same error mapping. Do not touch the hosted branch beyond moving the credit conversion into it.
