## Brief
# T3: API spending settings tab, agency overview, CSV export

## Goal

On a self-hosted deployment an agency owner can, per project, see DataForSEO spend and in-flight/estimated amounts, set a monthly (UTC) and a total USD limit, and pause/resume paid usage; and see one table across all the organization's projects with a date-range CSV export. Data comes from `ProjectDataforseoBudgetService` (landed in T-0001: `src/server/features/projects/services/ProjectDataforseoBudgetService.ts`). Design: decision `dataforseo-project-ledger`. Background, optional: `/home/nicoeft/workspace/webbzi/open-seo/dataforseo-project-budgets.md`, sections "App and MCP behavior" and "Refusals".

Service facts from T-0001 (report `/home/nicoeft/workspace/webbzi/open-seo/.notebook/reports/T-0001-a4.md`, "Choices I made"): sums are plain floats with noise like `2.47999999999999`, so round for display; `featureBreakdown` is all-time; `getOrganizationSummary` rows carry `projectId`, `availableUsd`, `archived`; `listRecentUsage`/`listUsageForExport` rows carry a derived `estimated` status plus `completedAt`, `runId`, `actorUserId` (export also `projectName`); `getProjectSummary`/`updateBudget` throw `NOT_FOUND` outside the org.

These surfaces exist only in self-hosted mode (`isHostedServerAuthMode()` false). In hosted mode the tab and page are not shown and the server functions refuse. Hosted users have Autumn credits instead.

## Build

1. Server functions `src/serverFunctions/projectDataforseoBudgets.ts`, TanStack server function -> service, following the existing serverFunctions middleware:
   - project summary, recent usage page, update budget: project-scoped through the existing project middleware (`requireProjectContext` and friends).
   - update budget additionally requires `requireOrgPermission` with `billing: ["manage"]`. General project-edit access must not be enough. Find how existing code checks that permission and reuse it.
   - organization summary and CSV export: organization-scoped, membership required. CSV export also requires `billing: ["manage"]` if that matches how other org-wide billing data is guarded; otherwise membership. Say which you chose.
   - Zod validators: limits finite, >= 0, at most two decimals, or null (unset). Zero and unset are different and must stay different end to end (an empty input means unset).
   - Errors are bare codes through `toClientError` (`AppError.details` never reaches the browser), so the UI reads amounts from the summary query, not from errors.
2. Project settings: an `API spending` tab in `src/client/features/projects/SettingsTabs.tsx` and its route/component. Show: this month's recorded cost vs monthly limit, total recorded vs total limit, in-flight reserved amount, amount available for new work, estimated (unsettled) amount labeled as estimated, tracking start date, the UTC month boundaries ("Month resets 1 Nov 00:00 UTC"), paused/unlimited/not-configured state, a feature breakdown, and paginated recent usage (time, operation, feature, cost or estimate, status). Owners edit the two limits and the pause switch in a TanStack Form; non-owners see read-only values.
3. Agency overview: one org-level page listing every project (archived ones labeled and filterable): project, this month, monthly limit, total, total limit, in progress, status (Available / Monthly limit reached / Total limit reached / Paused). Put it where org-level pages already live; link each row to its project's API spending tab. A date-range CSV export of usage rows from the same service, with recorded and estimated amounts in separate columns and opening-balance rows identifiable by operation.
4. `src/client/lib/error-messages.ts`: final copy for `PROJECT_BUDGET_EXCEEDED` ("This project's DataForSEO allowance has been reached. Review API spending in project settings.") and `PROJECT_DATAFORSEO_PAUSED` ("Paid DataForSEO usage is paused for this project. Resume it in project settings."). Treat both as expected conditions (not reportable, never an upgrade/credits prompt): check `NON_REPORTABLE_ERROR_CODES` in `src/shared/error-codes.ts`.

Money is displayed as USD with cents; costs below a cent display with more precision rather than "$0.00" when nonzero. Use TanStack Query hooks; invalidate the summary after a limit change. shadcn components in `src/client/components/ui/` are Base UI (compose with `render`, not `asChild`). Run the repo's `review-ui-states` checklist on the new screens (loading, empty, error, read-only).

If the service lacks a read you need, add it to the service/repository (T-0001 has landed, you own those read additions; do not change `admit`/`settle`).
